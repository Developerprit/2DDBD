## 0. 一句话定位

把《Dead by Daylight》的**非对称 1v4 恐怖追逐循环**完整搬进 2D 俯视角像素世界：
一名杀手对抗四名逃生者，围绕「修复发电机 → 开启大门 → 逃脱」与「击倒 → 挂钩 → 献祭」两条对抗轴线展开。

## 1. 需求确认结果（陌老师拍板）

| 议题 | 决策 |

### 3.4 网络架构

统一接口：

```gdscript
# src/net/net_base.gd
class_name NetBase extends RefCounted
func host(port: int) -> Error
func join(ip: String, port: int) -> Error
func is_server() -> bool
func tick(delta: float) -> void
```

三种后端：

| 后端 | 类 | 场景 |
|---|---|---|
| `Offline` | `NetOffline` | 单机，AI 填充 4 席 |
| `LAN` | `NetEnet` | 局域网主机权威，`ENetMultiplayerPeer` |
| `P2P` | `NetWebRTC` | 无服务器，`WebRTCMultiplayerPeer` + **手动 SDP 文本交换**（A 复制 offer → B 粘贴 → B 返回 answer） |

同步策略：**主机权威 + 客户端输入上行 + `MultiplayerSynchronizer` 状态下行 + 客户端本地插值**。
只有逃生者位置/状态、发电机进度、杀手位置/状态走同步；表现层（粒子/音效）本地播放。

## 5. 美术方案：程序化 SVG 像素精灵

### 5.1 为什么用 SVG
- Godot 4 内置 ThorVG 导入器，`.svg` 直接当纹理用；
- 整数倍栅格化（导入时设 `scale`）→ 边缘绝对锐利，真正像素完美；
- 矢量源文件体积小、配色可脚本批量替换（同一个骨架出 4 套角色配色）；
- 无外部素材依赖 → 零版权风险。

### 5.2 生成流水线

```
tools/gen_sprites.py
   ├─ 像素画布类 PixelCanvas(w, h)：set(x,y,color) / run-length 合并
   ├─ 骨架绘制函数：draw_humanoid(canvas, pose, palette, equipment)
   ├─ 姿态库：idle / walk / run / crouch / vault / injured / downed / hooked / carry / attack
   ├─ 物件绘制函数：generator / hook / pallet / window / locker / hatch / exit_gate / chest / beartrap
   ├─ 地形瓦片：grass / dirt / wood / stone / wall / tree / rock
   └─ 输出 → assets/sprites/**/*.svg
                             ↓ Godot 导入（scale=4, filter=nearest）
                         .godot/imported/*.ctex
```

### 5.3 尺寸规范

| 类别 | 逻辑像素 | 导入缩放 | 世界像素 |
|---|---|---|---|
| 角色 / 杀手 | 16 × 20 | ×4 | 64 × 80 |
| 发电机 / 钩子 | 24 × 24 | ×4 | 96 × 96 |
| 板 / 窗 / 柜 | 24 × 20 | ×4 | 96 × 80 |
| 地形瓦片 | 16 × 16 | ×4 | 64 × 64 |
| UI 图标 | 16 × 16 | ×2 | 32 × 32 |

### 5.4 音频方案
`tools/gen_audio.py` 用 numpy 合成：心跳（低频脉冲）、发电机（噪声+谐波）、惨叫（共振峰）、脚步（噪声包络）、钩子金属声、UI 音、环境风声、追逐 BGM（音序器生成）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| SVG 导入非整数倍导致糊边 | 观感崩坏 | 统一 `scale=4` + `filter=nearest` + 摄像机像素对齐 |
| AI 行为不自然 / 卡墙 | 单机体验差 | 用 `NavigationRegion2D` + `NavigationAgent2D` 寻路，行为树带超时回退 |
| Godot 4.5 API 变动 | 编译失败 | 全部代码针对 4.5 编写，交付前用 `--headless --check-only` 全量脚本校验 |
| P2P 信令复杂易错 | 联机不可用 | 保留 ENet 局域网为「稳」路线，WebRTC 为「无服务器」路线，两者共用角色逻辑 |
| 版权争议 | 无法发布 | 全部素材自制 + README 明确非商业粉丝作品声明 |

| **AI 翻越判定** | 第一版用「前方 1.1 格探针点是否靠近障碍」判断，几乎不触发（路径本来就绕开了窗户）。改为测量到障碍的真实距离 + 要求障碍在行进方向半平面内 + 逃跑时不校验「是否更接近目标」。压测中 120 秒内成功翻越 11 次（修复前恒为 0）。 |
| **血网成长系统** | 新增 `Bloodweb`（种子化节点生成 + 经济曲线）与 `BloodwebView`（环状界面）；`SaveData` 增加按角色存储的解锁集合；配装页面按解锁状态过滤技能。 |
| **F11 全屏** | `SceneRouter` 处理全局快捷键，切换无边框全屏（`WINDOW_MODE_FULLSCREEN` + `WINDOW_FLAG_BORDERLESS`），状态持久化。 |
| **杀手红光 + 视线遮挡 + 血欲** | 新增 `RedStain`（顶点着色扇形，随血欲档位变深变粗）；`CanvasModulate` 环境暗度 + 墙体光照遮挡体 + 角色 `PointLight2D`（开阴影）构成真正的视野遮挡；被墙挡住的敌人由 `MatchController._update_occlusion()` 自动半透明（状态色改走 `self_modulate`，把 `modulate.a` 让给遮挡）。血欲原本要求**每帧都有视线**才计时，实战中几乎不可能达成（压测恒为 0），改为「追逐状态」判定：有视线即可，或目标仍在 16 米内则延续（含 4 秒重置宽限）。 |
| **AI 感知三件套** | ① 逃生者把红光视为硬危险信号（`Killer.is_in_red_stain()`），且逃跑方向取**垂直于光轴**而非沿光轴；② 杀手新增 `Mode.SCRATCH`，跟随 16 米内最新划痕，并用次新划痕反推行进方向后外推 6 格，避免停在最后一个脚印上；③ 优先级明确为 视野中逃生者 > 划痕 > 最后已知位置 > 巡逻。压测中 150 秒内跟随划痕 81 次、触发血欲 2 档。 |
| **UI 溢出治理** | 配装页 12 个技能按钮横排约 1400 px，远超窗口宽度；改为 `HFlowContainer` 自动换行，所有页面套 `ScrollContainer` 保证矮窗口下按钮可达。 |

## 8.6 后续迭代记录（v1.3）—— 地图系统重做

陌老师反馈「地图很怪」。为了不靠感觉改，先做了一个**地图导出工具**
（`--dump-map`：把生成结果渲染成 PNG，并打印一份可读性报告），实测 6 个种子后发现旧生成器的硬伤：

| 指标 | 旧实现 | 现在 |
|---|---|---|
| 开放率 | 85% | 79%（且建筑是空心的，见下） |
| 平均「到最近墙的距离」 | 无此指标，目测大片空地 | **2.8 ~ 3.0 格** |
| 走廊格占比 | 0.3 ~ 0.6% | 2.6 ~ 3.3% |
| 板 / 窗不可达 | **11 ~ 17 个** | **0** |
| 钩子数量 | 20 ~ 29 个 | 12 个（原作标准） |
| 发电机↔最近钩子最远距离 | 31 格 | 8 格 |

**根因**：旧实现是「在一块空地上撒随机墙面」，没有任何结构。因此没有走廊、没有回廊、
追逐时无处可绕；而且板窗是事后在墙上随机打洞，大量生成在封死区里。

> 注意「开放率」本身不是好指标 —— 建筑是中空的，内部本来就可走。
> 真正反映「空得发慌」的是**每格到最近墙的平均距离**，这也是新增该指标的原因。

**重做方案**：

1. **地块规划**：80×80 划成 5×5 个 16×16 地块，每块分配蓝图
   （主建筑 / 中型建筑 / 户外体操区 / 小屋 / 户外掩体场 / 空地）。
   旧代码只允许在地图中心的 3×3 区域放建筑，实际最多 4 栋 —— 这是开放率降不下来的直接原因。
2. **蓝图建造**：外墙 + **按需开凿的门洞** + **内部环廊**（可绕行）+ 内室柱子。
   窗户只打在外墙上、且**确认两侧都可走**才生成。板窗从此是「建造出来的」而不是「事后撒的」。
3. **户外掩体**：L 形墙 / 栅栏段 / 平行双墙（形成走廊）/ 正中留缺口的栅栏，**全部正交排布**
   —— 正交形状一眼能读懂，随机角度的方块只会显得像噪点。
4. **物件落位**：发电机贴着建筑外墙约 3 格、彼此 ≥15 格；钩子先保证「每台发电机 13 格内必有一个」
   再撒满 12 个；地窖取离所有发电机最远的可走点。
5. **地面纹理**：从「逐格随机」改成**值噪声分片**（`FastNoiseLite`，低频 + pow 偏置），
   同类地面成块出现。旧做法相当于给地面加了一层电视雪花。
6. **每图独立布局参数**：`maps.json` 新增 `layout` 字段（建筑数量区间、掩体场比例），
   五种地形手感完全不同。此前五张图是同一个布局换配色。
7. **种子混入地图 id**：`rng.seed = seed_value ^ (hash(map_id) * 2654435761)`，
   否则同一 trial seed 下五张图布局完全一致。

顺带修掉两个**方向性 bug**：

- 窗户的 `dir` 原本给的是墙走向反 90°，导致 `landing_point()` 把人送到**沿墙方向**而不是穿墙；
- 木板拿到的 `dir` 是通行方向而不是板面走向，导致板旋转 90°、沿走廊躺着而不是横挡在通道上。

现在统一约定：**`dir` / `direction` 永远表示障碍物的延伸轴，穿越方向取其垂直**。

**验收**：全 5 张地图 `unreachable objects: 0`；180 秒压测中翻越 29 次、划痕跟随 56 次、
血欲正常升档、追逐→击倒→搬运→挂钩→献祭全链路无报错；一局时长回到约 8 分钟（此前约 4 分钟，偏快）。

### ② 挂钩系统：为什么必须大修

旧实现有**两份**阶段状态：`Hook.stage`（occupy 时设为 FIRST 后再也不动）和 `Survivor.hook_stage`（由 `tick_hook` 驱动）。
产生三个硬伤：

- 挣扎阶段（STRUGGLE）**从这个方向永远到不了**，钩子自己无法献祭任何人；
- 阶段判定是 `hook_count == 1 ? FIRST : STRUGGLE`，所以**第三次挂钩只是又开一次挣扎**，不会立即献祭；
- AI 的挣扎值被 `maxf(struggle, 0.25 + ...)` **永久托底** → 挂上钩的 bot 是**不死的**，整个献祭循环是装饰品。

重构后**阶段、计时器、挣扎条全部归钩子所有**，逃生者只镜像显示：

```
第一次挂钩 → FIRST    60 秒救援窗口 + 一次 4% 自救（失败即作废，不可反复掷骰）
第二次挂钩 → STRUGGLE 直接进入挣扎，每秒 -1/60，按住交互键 +0.019/秒
第三次挂钩 → 立即献祭，无计时器
同一人挂回同一根钩子 → 额外推进一个阶段
```

**AI 挣扎**：bot 不提供挣扎输入，且每秒有 50% 概率失误扣 0.01 → 净流失约 0.022/秒 → **约 46 秒被献祭**。
这个数字是刻意选的：短到"挂钩真的有威胁"（否则循环没意义），长到队友来得及跨半个地图来救。

顺带废弃了 `Hook.used`（钩子被用一次就永久退休，长时间对局会**没有钩子可用**），改为 `last_victim`：优先选"没挂过这个人"的钩子。

### ⑤ AI 脱手：决策层切目标没有落到状态机上

`_decide()` 里把 `goal_kind` 改成 `flee`，但状态机还停在 `interact`，而 **`InteractState` 根本不读 `move_input`**。
结果就是：杀手站在旁边，bot 依然在专心修机；已经决定放弃的发电机也照修不误。

修法：所有目标变更统一走 `_set_goal()`，它在目标真的变化时先 `_release_interaction()` 退出交互再改目标。
**"改主意"必须落到状态机上，光改意愿没用。**

**验收**：300 秒压测中观察到 `s1 → s2 → 献祭` 完整链路（死 3 人），全程 0 报错；
菜单与游戏内截图确认像素字体与中文回退均正常。

修法：所有目标变更统一走 `_set_goal()`，它在目标真的变化时先 `_release_interaction()` 退出交互再改目标。
**"改主意"必须落到状态机上，光改意愿没用。**

**验收**：300 秒压测中观察到 `s1 → s2 → 献祭` 完整链路（死 3 人），全程 0 报错；
菜单与游戏内截图确认像素字体与中文回退均正常。

## 8.8 后续迭代记录（v1.6.1）—— 翻越落点方向反了

陌老师反馈「翻越实际上只是往后退了一步」。定位到 `landing_point()` 的符号：

```
return global_position + normal * side * TILE * d      # 错：落回玩家来的那一侧
return global_position - normal * side * TILE * d      # 对：落到障碍对面
```

`side` 表示「玩家在障碍法线的哪一侧」，而落点必须在**对面**，所以法线项要**减**。
加上去的结果是落点回到起点一侧 —— 即"被推开约 1.35 格"，与体感完全吻合。

**这次没有靠肉眼看代码，而是加了两道可重复执行的防线：**

1. **几何自检**（`MapDump`）：对每个窗与板，从两侧各算一次落点，断言必须落在对面
   且越过障碍 1.5 格以上。关键点是它**调用真实的 `landing_point()`**（而不是在测试里重写一遍公式），
   这样测试不会与实现漂移。
2. **端到端测试**（`--test-vault`）：真的让一个逃生者跑完一次翻越，
   检查最终位置是否穿过障碍 —— 覆盖状态机、落点吸附与碰撞体这一段。

**并且验证了测试本身有效**：临时把符号改回去，自检立刻报 `0/19 correct   <-- BROKEN`。
（不验证的话，一个"永远通过"的测试比没有测试更危险。）

顺带补了一道保护：`_begin_vault()` 把落点吸附到最近可走格时，
**若吸附结果跑到了起点这一侧就放弃吸附** —— 否则一次本来正确的翻越会被"修正"成倒退。

## 8.9 后续迭代记录（v1.6.2）—— 木板三态与 AI 加强

### 木板：一次报告的两个独立缺陷

陌老师说「明明没下板，但画面和实际都有碰撞体积，而且下板之后的模型和碎了一样」。
这其实是**两个不相干的 bug**，同时发生才显得像一件事：

1. **竖立的板有碰撞体**。`_refresh()` 里 `if state == STANDING: add_blocker(...)` ——
   竖立的板是"靠在框里的板"，不是屏障，给它加碰撞体等于凭空封死一个玩家看得过去的门口。
2. **放下的板用了破碎贴图**。`dropped_tex = AnimBuilder.prop_texture("pallet_broken")`，
   所以一放下就"看起来被砸碎了"。

修法：**只有 DROPPED 有碰撞体**；新增第三张 `pallet_dropped` 贴图（完好的横躺板，
带接触阴影、比竖立版暗一档以体现"躺在地上"），并用一张 `state -> 贴图名` 的表固定三态映射。

顺带发现并修好两处死代码：
- `Pallet.try_stun()` **从来没有被任何地方调用** —— 板砸晕杀手的机制一直只存在于纸面上。
  现在 `drop()` 会检查 1.7 格内是否有杀手，有就砸晕。
- 杀手 `_try_traverse()` 还在尝试**翻越竖立的板**（现在竖立板不挡路了，没有可翻的东西）。

### AI 加强

四眼短板，逐条补：

| 短板 | 现状 | 现在 |
|---|---|---|
| 逃者不会下板 | 整局一块板都不放 | 杀手 5 格内且在板旁时主动下板 |
| 逃者不会绕圈 | 跑到板/窗旁边就**站着** | 以板/窗为中心**绕圈**（站到杀手对侧 + 切向偏移），并用成员变量锁定绕行方向避免抖动 |
| 修机不分工 | 谁近谁去，几台 bot 挤同一台 | 已有人修的机器扣 20 格权重；已在进度上的机器加权 |
| 杀手不预判 | 直线追当前位置 | 按 `目标速度 × 到达时间 × 0.55` 取提前量 |
| 杀手乱踩板 | 附近 1.1 格内有板就停下来踩 | 只踩**位于行进方向上**的板 |

**验收**：180 秒压测从 `dead=2 / gens=0-5` 改善到 `dead=0 / gens=2-5`，
`pallets=0/14 → 1-2/14`（此前整局恒为 0），`vaults` 从 8 升到 12。

### 新增断言测试 `--test-pallet`

因为"竖立的板不该有碰撞"这种约束**肉眼看不出来**（画面里板就是板），
所以加了一个会自己报错的测试：三种状态各设一遍，断言碰撞体数量与贴图名都符合预期。

同样做了**反向验证**：把碰撞条件改回 `!= BROKEN`，测试立刻报
`STANDING colliders=1 (want none) ... FAIL`，改回来又是 PASS。
（不验证的测试等于没有测试。）
